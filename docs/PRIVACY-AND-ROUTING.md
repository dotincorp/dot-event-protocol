# Privacy and Routing Policy v0.1

## Telemetry lanes

공통 이벤트 봉투는 공유하지만 lane마다 저장소, 접근 권한과 보존 정책을 분리한다.

| lane | 목적 | 예시 |
|---|---|---|
| product | 제품 사용성과 기능 채택 | 도구 선택, 리소스 열기 |
| learning | 학습 과정과 결과 | 평가 시도, 점수, 진도 |
| audit | 보안과 관리자 추적 | 권한 변경, 공유, 강제 로그아웃 |
| operational | 오류와 성능 | 동기화 실패, 지연시간 |
| realtime | 현재 세션 반응 | 클래스 참여, 공동 작업 상태 |

## Privacy classes

- `non_personal`: 사용자 또는 조직과 연결되지 않는 기술 상태
- `anonymous`: 재식별 가능한 안정 식별자가 없는 집계 전 이벤트
- `pseudonymous`: 가명 사용자·세션·리소스와 연결되는 이벤트
- `personal`: 직접 또는 간접 식별 정보가 필요한 이벤트
- `learning_record`: 답안, 점수, 진도처럼 학습 기록에 해당하는 이벤트
- `sensitive`: 장애, 건강 등 특별 보호가 필요한 정보
- `security`: 인증·권한·위협 대응 정보

## 금지 기본값

공통 제품 사용 통계에는 다음 원문을 넣지 않는다.

- 문서 본문, 점자 내용, 퀴즈 답안 원문
- 파일명, 수업명, 자유 입력 텍스트
- 실명, 이메일, 전화번호
- 이미지·음성·음악 원본
- 포인터 이동 전체 좌표
- 예외 메시지에 포함된 로컬 경로·토큰·서버 응답 본문

필요한 교육·감사 목적이 있다면 전용 이벤트 스키마, 별도 lane, 접근 제어와 보존 정책을 먼저 승인한다.

## 접근성 데이터

집중 모드나 키보드 사용 여부는 UI 기능 사용 통계일 뿐 장애 여부가 아니다. 클라이언트 또는 분석 단계에서 사용자를 장애 유형으로 추론하거나 프로파일링하지 않는다.

## 전송 원칙

- 이벤트 전송 실패가 앱 기능을 막지 않는다.
- 클라이언트는 배치, 재시도, 상한이 있는 오프라인 큐를 사용한다.
- `source + id`로 중복을 제거한다.
- 고빈도 동작은 포인터 단위가 아니라 완료된 명령 단위로 집계한다.
- 서버 수집 단계에서 스키마, 개인정보 등급과 lane을 다시 검증한다.
